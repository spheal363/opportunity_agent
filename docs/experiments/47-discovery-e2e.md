# 新経路の通し検証（#47）

**新規ユーザー・空の検証環境から、アプリだけで動かした。**
人手で訂正した 20 件は使っていない。入力は希望と地域だけ。
実行のたびに独立した DB を作り、**ユーザーの実 DB は使っていない。**

`backend/scripts/e2e_discovery.py` / 生データは `docs/experiments/47-e2e/`。

## 動いたこと

    画面入力（PUT /api/profile）
      -> 探索（POST /api/agent/runs, SEARCH_ROUTE=discovery）
      -> 候補一覧（GET /api/opportunities）
      -> 詳細確認（POST /api/opportunities/{id}/detail-check）
      -> 訂正の反映

## 実測で見つけて直した不具合

**コードの検査では出ず、実際に走らせて初めて出たものばかり。**

| 症状 | 原因 | 直し方 |
|---|---|---|
| 一覧が 0 件（DB には 12 件） | 候補の `status` 未設定で一覧 API の対象外 | `recommended` を付ける |
| 書式見本が候補になる | 依頼文の見本行をそのまま返してきた | 見本行を落とす |
| 会期が「対象期間外」 | 9/9〜11/29 を各日の所属で判定していた | **重なりで判定**し、期間内に参加できる日があるかは**未確認**と書く |
| 同じ回が 2 件 | 「ポケモン & アスリート」と「ポケモンとアスリート」 | **同じ日・同じ会場なら同じ回**として統合 |
| URL が全件 null | 引用記法 `([例](https://…))` で返っていた | 行の中に実在する URL を取り出す（組み立てない） |
| 詳細確認で例外 | 抽出スキーマに `application_url` は無い（`url` が持つ） | `url` を使う。**取得元と同じなら申込先を確かめたことにしない** |

**回答と引用 URL を保存していたおかげで、URL の件は原因を特定できた**
（`agent_runs.discovery_answers`）。
