## Opportunity Agent

目標と興味から、AI Agent が自律的に Web を探索し、**自分では検索しなかった機会**を
見つけて、確認したうえで予定にするところまで支援する。

設計思想は **Autonomous discovery, human-controlled action.**
発見と評価は Agent が自律的に行い、外部世界に影響する操作は人間に戻す。

## 今回のデモで実際に起きたこと（run `run_debcf295e6d4`）

入力は「今後60日以内に、東京またはオンラインで参加できるイベントに参加したい。
ハウス／テクノのイベント、DTM・作曲のワークショップ、ハッカソン」。
背景には「将来は起業したい」があるが、**今回の目的はイベント参加**と書いた。

Agent は目的と背景を分け、4 つの探索方向を立てた。

```
ハッカソン 東京 オンライン 募集 2026年10月
DTM 作曲 ワークショップ 東京 オンライン 参加 2026年10月
ハウス テクノ イベント 東京 2026年10月
音楽制作 ハッカソン 募集 東京 オンライン   ← 音楽 × 技術の交差
```

目標の要約に起業は出てこない。対象期間（run 開始時に確定した 60 日）の年月が
クエリに入っている。

結果はこう分かれた。

| 枠 | 件数 |
| --- | --- |
| **今後60日以内と確認できたイベント** | **1** |
| 期間より前に始まり、いまも続いている | 1 |
| 日程を確認できなかった候補 | 1 |
| 開催期間の条件を当てていない候補 | 2 |
| 参加候補から外れたもの（開催終了・受付終了） | 3 |

**期間内は 1 件。3 件ではない。** 0 件のときは 0 件と表示し、別枠の候補で埋めない。

### 見つけた 1 件と、その限界

`YAGI BPM EXHIBITION 2026`（Womb・渋谷）。開催日 2026年9月22日、受付中を公式ページで確認。
参加条件「20歳以上・写真付き身分証明書」も取れた。

**ただし希望どおりではない。** ページのジャンル欄は
**エレクトロ／ミニマル／アンビエント**で、ハウス／テクノとは書かれていない。
推薦理由が「ハウス/テクノ系のイベントとして」と書いたのは LLM の推測で、出典に反する。
費用（DOOR ¥4000）と開始時刻（23:00）も取りこぼした。

言えるのは **「期間内・受付中の音楽イベントを 1 件出せた」**まで。

## 作ったもの

### 受付終了を「参加できる」と見せない

Web の告知は古いまま残る。**日付が古いから閉じるのではなく**、公式ページを
読み直して、推薦する行動（応募・参加登録）に対応する締切や開催終了が
根拠になっているかで判定する。

実測で、申込締切が 2023 年 12 月のアクセラレーターが推薦に残っていた。
検証は「申込の締切が過ぎています」と書いていたのに、締切の種類を決められず
「参加の締切か分からない」として通していた。これを直した。
早割や登壇者募集の締切は、参加を塞がないので従来どおり通す。

### 期間と受付を別の軸で持つ

「今後60日以内か」と「申し込めるか」は別。期間内でも締め切られていることがある。
コミュニティや求人には開催期間の条件を当てない。ただし**種別だけで「通年」とは
断定せず**、締切と受付は必ず確認して表示する。

日時が取れなかったものは「日程未確認」として分ける。**推測で期間内に入れない。**

### 安いモデルを試し、採用しなかった

外部ページを読まない「検索計画」を安いモデルに替えられるか実測した。
固定入力 3 件 × 2 設定 × 2 回 = 12 リクエストを、プロンプト修正の前後で実施して
**累計 24 リクエスト**。実費は OrcaRouter から取得した確定値。

速度は約 3 倍、実費は約 14 倍の差（$0.0227 → $0.0016 / 6 件）。Schema 通過率は同じ。

それでも採用しなかった。目標の軸が 2 つある入力で、**安いモデルは片方
（起業）の検索方向を作らないことがあった**。プロンプトに規則を足して測り直しても
6 件中 2 件で同じ欠落が起きた。

**限界。** 標本は各 6 件と小さい。判定に使った機械検査も、判別力があったのは
4 軸のうち 1 軸だけで、言い換え（「新規事業」「アントレプレナー」）は見逃す。
言えるのは「**この条件で、安いモデルへ替える根拠は得られなかった**」まで。

**この比較は探索の一工程を測ったもので、上のデモ run の結果とは別の実験。**

### Prompt Injection を前提に組む

Web 本文は信頼しない。指示らしき文は LLM に届く前にコードで取り除き、
見つかったページから取った候補は推薦しない。アクセス確認ページ
（Cloudflare の "Just a moment..." など）は取得失敗として扱い、機会にしない。

## Calendar（**プレビューまで確認済み・実登録は未確認**）

候補から「カレンダーに追加」を押すと、**実際に送る内容そのもの**を確認画面に出す。
予定名・日時・タイムゾーン・場所・出典 URL・空き状況。

- 時刻が分からない催しは**終日予定**として追加する（09:00 などに補完しない）
- 日付自体が不明なら登録しない
- 「予定の追加は参加申込ではありません」を明示
- 同じ候補は何度押しても 1 件しか入らない

**デモ環境は Google 未連携のため、実際の書き込みは確認していない。**
プレビューの表示までが確認済みで、実登録の成功ではない。
