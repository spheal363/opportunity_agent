# デモの手順と根拠（2026-09-22）

**実行済みの run を使う場面はその都度明示する。** 実登録の成功として説明しない。

## 事前

```bash
cd backend && .venv/bin/uvicorn main:app --reload --port 8000
cd frontend && npm run dev
```

構成は既定のまま（Serper + Jina + Jev + prefilter、`LLM_ROUTING=policy`）。

## 1. 入力（画面から）

`http://localhost:5173/app` →「目標・興味を編集」。

**初回フォームは 4 項目**（#47 で簡素化）。

| 欄 | 入れるもの |
| --- | --- |
| お名前（任意） | デモ利用者 |
| **いま、やってみたいこと** | ハウスやテクノなど四つ打ちの音楽を楽しめるイベントに行きたい<br>初めての曲作りにつながるDTM・作曲のワークショップに出たい<br>エンジニアとしてプロダクトを作れるハッカソンに参加したい<br>ポケモンのイベントにも参加したい |
| 将来の目標（任意） | 将来は自分のプロダクトで起業したい |
| 活動したい地域 | 東京 / オンライン |

**見せどころ。** 「いま」と「将来」が**別の欄**になっている。
将来の起業は補足で、**今回探す機会の必須条件にしない**。
興味タグは無くても、自由文の希望がそのまま検索・選別・評価へ届く。

**見せどころ。** 「今回の目的（イベント参加）」と「背景の目標（起業）」を
分けて書いてある。次のステップで、要約が起業に寄らないことを見せる。

**正直に言うこと。**

  エレクトロ／ミニマル／アンビエント。推薦理由の
  「ハウス/テクノ系のイベントとして」は**LLM の推測で、出典に反する**
- 「音楽イベントである」「今後60日以内（今日）」「受付中」は出典で確認できた
- 費用と開始時刻を取りこぼしている。**未確認として見せる**

つまり **「期間内・受付中の音楽イベントを 1 件出せた」までが言えること。**
「希望どおりのハウス／テクノを見つけた」とは言わない。

## 5. Calendar（**プレビューのみ**）

候補 →「この機会を見てみる」→ 確認パネル。

    予定名 / 日時 / タイムゾーン / 場所 / 出典 URL / 空き状況

- 日付のみの候補は**終日予定**として追加する旨を出す（時刻を勝手に決めない）
- 「予定の追加は参加申込ではありません」を明示
- 二重登録は Opportunity ごとの固定 ID で防ぐ

**このマシンは Google 未連携のため、実登録は行っていない。**
確認パネルまでは Google を呼ばずに出る（`GET /api/calendar/preview`）。
実登録には接続が要る。

```bash
# backend/.env に GOOGLE_CLIENT_ID / GOOGLE_CLIENT_SECRET を設定してから
cd backend && .venv/bin/python -m scripts.google_auth
```
